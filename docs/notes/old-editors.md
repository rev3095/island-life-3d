# 예전 캐릭터 · 배경 편집기 흐름 (P36 이전)

P36 (2026-11-11) 에 편집기를 셋으로 나누면서 CLAUDE.md 에서 옮겨 온 글이다. 지금은 모델·그림 = 리소스 편집기 "리소스 요청 확인" (`docs/notes/p36-res-editor.md`), 주민 성격·대화 = 스토리 편집기 「주민」 탭 "스토리 반영", 방 배치 = 요소 편집기 「방 배치」 탭 "요소 반영". 예전 편집기와 그 저장소는 지우지 않고, 남은 요청이 오면 아래대로 처리한다. "리소스 요청 확인" 의 순서도 이 흐름이 바탕이다.

- (예전 — 모델·그림 요청은 "리소스 요청 확인", 성격·대화는 스토리 편집기, 방 배치는 요소 편집기로 옮김. 예전 편집기와 저장소는 지우지 않는다) `editor.html`(캐릭터 편집기, https://claude.ai/artifact/FTCqiHtFPcACcQEULNbUX2) · `bg-editor.html`(배경 편집기, https://claude.ai/artifact/LuEvzroBSW2RFhVWvm6tkh) 은 아티팩트로 공개되며 capabilities `db`·`assets`·`user` 를 쓴다 (캐릭터 편집기는 `applied`·`history` 쓰기 admin). 사용자가 레퍼런스(이미지·영상→장면 6장)와 프롬프트로 요청을 저장한다: 캐릭터 `refs`/`requests`, 배경 `env-refs`/`env-requests` 컬렉션.
- (예전, 남은 요청이 있을 때와 "리소스 요청 확인"의 바탕 순서) 채팅에 "요청 확인"(캐릭터) / "배경 요청 확인"(배경)이 오면: ArtifactData 로 `status:'new'` 요청 읽기 → `working` → 레퍼런스는 Artifact read `path=<asset id>` 로 내려받아 직접 본다 → 스펙·빌더 수정 (`version` 올리고, 확정이던 요소는 status `review` 로) → 재빌드 → 크기가 바뀌었으면 같은 스펙의 `world` 칸(충돌·집터) 맞추기 → `node --test tests/` (`assets.test.mjs` 가 교체 약속 검사) → 같은 아티팩트에 다시 publish (바뀐 파일만 `files` 로, 한 번에 255개. bg-editor 는 아티팩트 한 버전에 파일 511개까지라 요소별 스펙·통계 대신 `node tools/build-editor-index.mjs` 로 만든 묶음(배경·가구·아이템·실내 `editor-index.json` + 배경·가구·아이템 모델 `assets/<env|furniture|items>/editor-models-<n>.json`)을 올리고 `specs/`·`.stats.json`·모델 `.glb.json`·아이템 아이콘 파일은 올리지 않는다. 렌더·썸네일도 묶음(`assets/<env|furniture>/editor-renders-<n>.json`·`editor-thumbs.json`, M10-P2 D97-A) — 게시 파일 61개, 올릴 목록은 `dist/bg-editor/publish.json` (`batches`, 첫 차례 `mode:"replace"`). 아이템 탭은 `bg-editor.html` `AREAS` 의 `cats`·`CAT_LABEL` 에 있는 분류만 보여 주니 새 아이템 분류는 거기에도 더한다) → 게임 링크도 다시 게시 (웹 배포 절) → 요청을 `done` + `reply` + `doneVersion` 으로 갱신 → 반영 기록 `applied/<character|env>`·`history` → 편집기 홈 `status/<id>`.
- (예전) 배경 편집기 영역 — 지금은 배경·가구·아이템·무늬는 리소스 편집기, **방 배치(주민 방·상점·박물관·달빛 가게·천막)는 요소 편집기 「방 배치」 탭 → "요소 반영"**: 배경 · 가구 · 아이템(`slug` `item-<slug>`, `category:'item'` + `group`) · 실내 무늬(`wp-0N`·`fl-0N`, 간격 = `fields.params.sizeX/sizeY` → 스펙 `pattern.size`) · 방 배치(`rm-0N`, `category:'room'` — 상점·박물관 `place-shop`·`place-museum` 도 같은 격자, 크기는 방 파일 `size`, 붙박이 FU-35–42 모델은 `assets/furniture/fixtures`). 방 요청에는 `layout`(그대로 `assets/interior/rooms/<slug>.json` 의 name·note·wallpaper·floor·host·furniture)과 `problems`(편집기 배치 검사, 비어야 정상)가 붙는다. RM-07(단풍)처럼 파일이 없는 방은 `kind:'add'` → 새 방 파일 + `interior/index.json` + `interior.js` `WEB_FILES` + `tests/interior.test.mjs`. 무늬·방은 Blender 없이 JSON 만, 아이템은 `node tools/build-item.mjs <slug>`. 자세한 순서는 `docs/notes/m6-p2-bgtabs.md`.
