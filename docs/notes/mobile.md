# X1 휴대폰·조작 (p6-mobile) — 만든 것·정한 것·제안

브랜치 `p6-mobile` (main 326b8bc 에서), 포트 4195. 고친 곳: `src/core/input.js`, `src/ui/` (새 파일 `toolring.js`·`variants.js`), `index.html` 의 `<head>`. 다른 폴더는 건드리지 않았다.

## 만든 것

### 터치 조작 (`src/core/input.js`)
- **떠다니는 패드**: 왼쪽 아래 넓은 곳(세로 화면 왼쪽 46%·아래 40%, 가로 화면 왼쪽 38%·아래 70%) 어디를 눌러도 그 자리에 패드가 생긴다. 쉴 때는 왼쪽 아래(20px·안전 영역 안)에 128px 원으로 보인다.
  손가락이 원 밖(반지름 50px)으로 나가면 패드가 따라온다. 덜 민 곳(14% 아래)은 서 있기, 92% 넘게 밀면 달리기 — 달릴 땐 손잡이가 주황색.
- **손을 떼면 멈춤**: `pointerup`·`pointercancel`·`lostpointercapture`, 창 바깥으로 나가기(`blur`)·화면 숨김(`visibilitychange`) 때도 바로 0 으로.
- **A(행동) 78px 주황·B(줍기) 64px 크림**, 오른쪽 아래 비스듬히 (A 오른쪽 20·아래 62, B 오른쪽 108·아래 20 + 안전 영역). 글자 아래에 작게 '행동'·'줍기'. 누르는 동안 눌린 모양(`is-down`), 포커스를 뺏지 않는다(창 안에서 포커스 = 커서라서).
- **두 손가락**: 패드와 A/B 가 손가락(pointerId)을 따로 본다 → 걸으면서 A·B 를 누를 수 있다.
- **창이 열리면**(`input.enabled = false`) 패드는 숨고 누를 수 없게, A/B 는 흐리게 남는다 (A = 고르기, B = 뒤로). 그래서 창·대화창이 패드 자리까지 쓸 수 있다.
- 터치 모양 CSS 는 `input.js` 가 `<style data-touch-controls>` 로 직접 넣는다 (어느 페이지에서 `createInput` 을 써도 같은 모양, `index.html` 에서 옛 CSS 를 뺐다).
- 터치 화면 노트북·트랙패드 태블릿: `(pointer: coarse)` 가 아니어도 **처음 손가락으로 만질 때** 패드를 만든다 → 이벤트 `input:touch {on: true}` → ui 가 `pk-touch` 를 붙인다. 주소 `?touch=1` 은 늘 켜기, `?touch=0` 은 끄기.

### 화면 맞춤 (`src/ui/ui.css`)
- **안전 영역**: `index.html` 의 `:root` 에 `--safe-top/right/bottom/left` (= `env(safe-area-inset-*)`). `ui.css`·`input.js` 가 이 값을 쓰고, 없으면 `env()`. 확인할 때 `document.documentElement.style.setProperty('--safe-top', '47px')` 로 노치를 흉내 낼 수 있다.
- **세로 휴대폰**: 창은 A/B 위(아래 150px + 안전 영역)까지, 대화창은 아래 152px. 도구 단추(64px)는 A 바로 위(오른쪽 27·아래 150).
- **가로 휴대폰(높이 520px 아래)**: 창 머리를 얇게(제목 이름표는 위 테두리에 걸치고 ✕ 는 모서리 밖으로), 창은 왼쪽 12px ~ 오른쪽 A/B 앞(182px)까지 (패드가 숨으니 왼쪽도 쓴다).
  가방 = 왼쪽 5×4 칸(칸 크기를 화면 높이에 맞춤 44~64px) + 오른쪽 설명, 섬폰 = 넓은 판에 앱 6개 한 줄, 지도 = 왼쪽 지도(높이 맞춤) + 오른쪽 장소 목록 스크롤, 상점 진열 2줄, 확인 창 단추는 가로로.
- **작업대 세로 화면**: 고른 레시피(그림·재료·만들기)를 위에 붙여 두고(sticky) 목록만 스크롤.
- **손가락 크기**: 터치에서 탭·나눔 단추·지도 장소·슬라이더 44px, 스위치는 보이는 34px + 누르는 곳 46px, HUD 메뉴 단추 50px.
- 떠오르는 hover 효과는 `@media (hover: hover)` 에서만 (휴대폰에서 누른 뒤 떠 있는 채로 남지 않게), 손가락은 `:active` 눌림만.
- 터치에서 창 본문은 `touch-action: pan-y`, `#ui` 는 `pan-x pan-y` → 스크롤은 되고 두 손가락 확대·두 번 눌러 확대는 막힘.

### 도구 고르기 고리 (`src/ui/toolring.js`, 새 `ui.tools.open()`)
- HUD 도구 단추를 누르면 **맨손 + 가방에 있는 도구**가 동그랗게 펼쳐진다 (세로 화면은 엄지 가까이 아래쪽). 한 번 눌러 고르면 창을 닫고 `tool1~5`/`toolNone` 의도를 보낸다 → 드는 규칙은 그대로 gather(`toolbelt.js`)가 정한다.
- 가운데에 이름·'지금 든 것', 도구 밑에 남은 사용 횟수. 키보드: 방향키·Enter·1~5·0, Esc 닫기. 휴대폰: A 고르기·B 닫기.
- 키보드 Q·E·숫자키는 그대로. 예전처럼 '단추 = 다음 도구' 가 필요하면 `createHud` 에 `openTools` 를 안 넘기면 된다.

### 가방 가구 변형 색 이름 (`src/ui/variants.js`, W3 부탁)
- 칸에 `variant` 가 있으면 `assets/furniture/index.json`(아이템 → slug) 과 `assets/furniture/specs/<slug>.json` 의 `variants[v].label` 을 읽어(' (기본)' 은 뺌) 보여 준다.
  - 칸 왼쪽 위 **색 점** (변형들이 바꾸는 첫 팔레트 칸 색, 기본 변형은 스펙 기본 팔레트) — 썸네일이 기본 색이라 파란 소파도 주황으로 보이던 것을 보완.
  - 설명 줄·말풍선 팁에 **이름표** `● 파랑`, 화면 읽기 이름 `소파 (파랑)`.
  - 상점 팔기 문구·알림: `파랑 소파를 🌰 750에 팔까요?`.
  - 주민 사진(`variant` = 주민 slug)도 같은 방법으로 `보리` 처럼 나온다.
- 스펙은 처음 볼 때 한 번 받아 두고(받으면 열린 가방을 다시 그림), 못 받으면 변형 이름(`blue`)을 그대로.

### 그 밖
- 섬폰 설정 '화면'에 **전체 화면** 스위치 (`document.fullscreenEnabled` 일 때만 보임 — 아이폰 Safari·막힌 아티팩트 틀에선 안 보인다). 휴대폰에선 '키 안내 보기' 줄을 숨김 (키 안내 자체가 없어서).
- 가방: 누른 칸에 직접 포커스를 준다(iOS 는 눌러도 단추에 포커스가 안 감 → 설명 줄·A 버튼이 그 칸을 보게). 마우스가 올라간 칸만 설명 줄을 바꾼다.
- `index.html` `<head>`: viewport 에 `interactive-widget=resizes-content`(글자 입력 때 자판만큼 화면이 줄어 입력칸이 가려지지 않게), `theme-color`, 홈 화면 앱 메타(`mobile-web-app-capable`, `apple-mobile-web-app-*`), `format-detection`, `text-size-adjust: 100%`(아이폰 가로 화면 글자 커짐 막기), `overscroll-behavior: none`(당겨서 새로 고침 막기), `-webkit-touch-callout: none`.

## 정한 것 (다른 트랙이 알아야 할 것)
- `ctx.input.enabled` 는 이제 getter/setter (쓰는 법은 같다). 끄면 패드가 숨고 잡고 있던 패드도 놓는다 → 창이 닫힌 뒤엔 손가락을 다시 대야 걷는다 (창이 닫히자마자 저절로 걷는 일 방지).
- `#touch-controls` 는 `#ui` 안 맨 뒤, `z-index: 5`. 패드 영역(위 퍼센트)은 손가락을 가로챈다 → **#ui 에 누를 수 있는 DOM 을 붙이는 모듈은 그 영역과 A/B·도구 단추 자리를 피한다.** 창이 열려 있을 땐 패드 영역이 손가락을 받지 않는다.
- 안전 영역은 `--safe-top/right/bottom/left` 를 쓴다 (`env()` 직접 대신) — 노치 흉내 확인이 된다.
- HUD 도구 단추 = 도구 고르기 고리 (다음 도구 아님).

## 계약 제안 (CONTRACTS.md 에 넣었으면 하는 것)
1. `input`: `enabled` getter/setter, `enableTouch()`, 이벤트 **`input:touch {on}`** (터치 조작이 생겼을 때 — coarse 기기는 `createInput` 안에서 바로라 아무도 못 들을 수 있다 → 모듈은 init 때 `ctx.input.touch` 도 같이 본다, 그 밖의 기기는 첫 터치 때), 주소 `?touch=1|0`.
2. `ui.tools.open() → Promise<{ tool } | null>` — 도구 고르기 고리 (고르면 `tool1~5`/`toolNone` 의도를 보낸다).
3. CSS 변수 `--safe-top/right/bottom/left` (`index.html :root`) — #ui 에 DOM 을 붙이는 모든 모듈이 이것으로 노치를 피한다.
4. 터치 조작 자리 (#ui DOM 이 피할 곳): 세로 = 왼쪽 46%·아래 40%(패드), 오른쪽 아래 180×230px(A·B·도구 단추) / 가로(높이 560 아래) = 왼쪽 38%·아래 70%, 오른쪽 182px.
5. (gameplay 공용, 조정 세션) **`interactions.peek(intent) → { name } | null`** — 지금 A/B 를 누르면 무엇을 할지(첫 `test` 가 맞는 처리기 이름). 휴대폰에서 A 버튼 글자를 '말 걸기'·'흔들기'·'들어가기' 처럼 바꿔 보여 주고 싶다. 지금은 `list()` 가 `test` 를 주지 않아 ui 가 알 수 없다. 처리기에 `label` 을 달 수 있으면 더 좋다 (예: `town:talk` → '말 걸기'). `test` 에 부작용이 없어야 하고 0.2초마다 부를 수 있어야 한다.

## 다른 트랙에 부탁
- **X3 첫날 흐름**:
  - 밤톨 안내 `lines/bamtol.js` 의 `intro.touch` 에 도구 단추 한 줄: "오른쪽 아래 동그란 도구 단추를 누르면 가방에 있는 도구를 골라 들 수 있어요." (지금 터치 안내엔 도구 바꾸는 법이 없다)
  - 이름 정하기 입력칸은 `font-size` 16px 이상 (아이폰이 16px 아래 입력칸에서 화면을 확대한다). viewport 는 `interactive-widget=resizes-content` 라 자판이 뜨면 화면 높이가 줄어든다 → 입력 창은 화면 가운데·위쪽에.
  - 첫날 할 일(체크리스트) DOM 은 왼쪽 위 시계 아래나 위쪽 가운데에 두고 `--safe-top/left` 를 더한다. 패드 영역·A/B 를 피하거나, 눌러야 하면 `z-index: 6` 이상.
  - 창(이름 정하기 등)을 열 때 `ctx.input.enabled = false` (또는 ui.confirm/panels) 를 쓰면 패드가 숨는다.
- **X2 성능·카메라**: 세로 휴대폰(375×812)은 가로 시야가 좁다 (세로 FOV 32° 고정이면 가로 ≈ 15°). 세로 화면에서 FOV·거리를 조금 넓혀 주면 좋겠다. 카메라 핀치 확대(`camera.js`)는 캔버스에서만 받는다 — 패드·A/B 위 손가락은 캔버스에 안 가서 걷기·핀치가 섞이지 않는다.
- **X4 웹 배포**: `index.html` `<head>` 의 새 메타·`:root --safe-*` 변수를 빌드 결과에도 그대로. 터치 CSS 는 `input.js` 가 넣으니 따로 묶을 파일은 없다 (새 파일 `src/ui/toolring.js`, `src/ui/variants.js` 만 목록에 추가). 가구 변형 이름은 `assets/furniture/index.json`·`specs/*.json` 을 `ctx.assets.loadJSON` 으로 읽는다 → 배포 묶음에 그 JSON 들이 있어야 한다. 아티팩트 틀에서 전체 화면이 막히면 설정 줄은 저절로 숨는다.
- **조정 세션**: 위 계약 제안 5 (`interactions.peek`).

## 확인한 것 (휴대폰 흉내: 브라우저 창 mobile 프리셋 375×812, 터치 기기 흉내)
- 터치 이벤트로 끝까지 (패드는 합성 `PointerEvent` touch, A/B 는 합성 터치 또는 실제 탭):
  첫 터치 → 밤톨 안내(터치용 안내 줄 나옴, A 로 넘기고 선택지 탭) → HUD 도구 단추 → 고리에서 낚싯대 → 패드로 나무까지 걸어가 맨손 A 흔들기 → 나뭇가지 떨어짐 → B 줍기 →
  선착장 끝에서 낚시(A 던지기, 입질 때 A) 문어·고등어·전갱이 → 상점 문 A → '팔래요' 탭 → 가방 팔기 → 고등어 확인 '팔게요' 실제 탭(500 → 650) → B 로 가방 닫기 → 사기 탭 → 튤립 씨앗 확인을 A 로(650 → 410) →
  박물관 A → '기증하러 왔어요' → 문어 기증(A) → B → 집 문 A → 실내 빈 바닥 A → '가구 놓기' 가방(파란 소파에 색 점) → 소파 놓기(variant blue 유지) → 소파 A → '돌리기'(rot 0 → 1) →
  작업대 A → 통나무 의자 '만들기' 실제 탭 → B 닫기 → HUD 섬폰 → 설정(외곽선 끔, 배경음 40%) → B 두 번 → 문 매트 A 로 집 밖.
  (먼 거리는 `player.teleport` 로 옮긴 뒤 마지막 몇 걸음만 패드로 걸었다 — 숨긴 미리보기 창에서 한 프레임이 120ms 넘게 걸려서.)
- 두 손가락: 패드를 끝까지 민 채(달리기) A 를 누르고 떼도 계속 걷고, 패드를 떼면 `move = 0`·달리기 끔.
- 창이 열리면 패드가 숨고(`is-ui`) 닫히면 돌아온다. A = 포커스된 단추 누르기, B = 뒤로/닫기.
- 화면: 375×812, 390×844(노치 위 47·아래 34 흉내), 812×375(왼쪽·오른쪽 47·아래 21 흉내), 768×1024 에서 HUD·대화창(선택지)·가방·섬폰·지도·상점·작업대·확인 창·박물관·도구 고리가 잘리지 않음. 창 단추 크기 44px 이상(`offsetWidth/Height` 로 잼).
- 데스크톱(터치 없음): 키 안내 보임, 패드 없음, E·숫자키·I·Esc 그대로, 도구 단추 클릭 → 고리, 고리에서 숫자키. 첫 터치 때 패드 생김(`input:touch`).
- `node --test tests/` 114개 통과, 콘솔 오류 없음.

## 못 한 것
- **실제 휴대폰에서 안 해 봤다** (iOS Safari·Android Chrome). 안전 영역은 CSS 변수를 덮어써서 흉내 냈을 뿐 실제 `env()` 값은 못 봤다.
- 진짜 두 손가락은 못 했다 — 합성 `PointerEvent` 두 개(다른 pointerId)로만 확인. 실제 기기의 암묵 포인터 캡처·`pointercancel`(브라우저 제스처) 동작은 못 봤다.
- 전체 화면 스위치는 사용자 몸짓이 필요해 합성 클릭으로는 못 눌렀다 (줄이 보이는 것만 확인).
- 두 손가락 확대 막기(`touch-action`)·당겨서 새로 고침 막기·자판이 뜰 때 화면 줄기는 CSS·메타만 넣었고 기기에서 확인 못 함.
- 휴대폰 성능(프레임 시간)은 X2 몫이라 재지 않았다.
- A 버튼 글자를 상황에 맞게 바꾸기(말 걸기·흔들기)는 `interactions.peek` 이 있어야 해서 못 했다 (위 제안 5).
