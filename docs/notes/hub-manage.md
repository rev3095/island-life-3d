## "열리지 않음" — 원인 후보와 확인할 것

이 세션도 claude.ai 에 로그인이 안 돼 게시본을 직접 보지 못했다 (내장 브라우저로 링크를 열면 "이 페이지를 보려면 로그인하세요" 화면만 나온다). 그래서 게시본 글을 읽고 보기 창 약속(contract 0.2.92)과 맞대어 실패할 곳을 모두 막았다.

1. **로그인 안 된 창에서 연 경우** — Claude 데스크톱 앱 안의 브라우저 창(미리보기)으로 링크를 열면 로그인 화면만 보인다. 이 세션에서 그대로 겪은 것이라 가장 그럴듯하다. → 로그인된 브라우저(크롬 등)나 claude.ai 에서 연다.
2. **본 스크립트가 `board-kit.js` 에 기대어 있었음** — 예전 홈은 첫 줄에서 `window.ApplyLog` 를 바로 풀어 써서, 그 파일이 늦거나 못 오면 스크립트 전체가 멈추고 카드가 하나도 없이 "현황을 불러오는 중…" 에 머문다 (열리지 않은 것처럼 보임). → 대신 도구 + 실패 상자에 "파일을 못 받음 — concept/board-kit.js".
3. **글꼴 stylesheet 가 화면을 막음** — `<link rel="stylesheet" href="fonts.googleapis.com…">` 는 글꼴 서버가 늦으면 그 아래를 그리지 않는다 (흰 화면이 오래). → 스크립트로 나중에 붙임.
4. **저장소가 답하지 않거나 구독 하나만 실패** — 예전엔 끝없이 "불러오는 중" 이거나 전부 "현황 없음". → 15초 표시, 칸마다 이유.
5. 플랫폼 쪽 (권한·앱 버전) — 새 홈에서도 화면이 비면 이쪽. 맨 위 상자가 뜨면 그 글이 단서.

## 설계 결정

- **목록은 Claude 가 쓰는 문서(`catalog/<분류>`), 홈은 읽기만.** 아티팩트는 저장소 파일도 다른 아티팩트 저장소도 못 읽는다. 분류마다 문서 하나 (가장 큰 아이템 21 KB, 256 KiB 안) — 구독 하나(`collection('catalog')`)로 다 받는다. 페이지 글에 목록을 박지 않아서 반영 때 홈을 다시 게시하지 않아도 된다.
- **상태는 파일이 정본.** 스펙·주민·방·장면은 파일 `status` (approved | review), 확정·다시 열기는 파일을 고치고 `--index` → 편집기 다시 게시 → 목록 다시 만들기. 값 데이터(소리·지도·숫자·스타일)와 보드 결정은 확정 단계가 없어서 홈 `marks/<분류>` 에 "검수 대기" 표시만 둔다 (목록을 다시 만들어도 남게 따로 문서). 게임은 status 로 거르지 않아서 다시 열어도 게임에서 빠지지 않는다.
- **요청은 홈 저장소 `manage` 한 곳.** 편집기마다 요청 모양이 달라서 홈이 각 편집기 요청 컬렉션에 쓰지 못한다 (다른 아티팩트 저장소라 쓸 수도 없다). "전체 요청 확인" 때 Claude 가 읽어 그 편집기 흐름으로 처리하고 `reply` 를 단다. 쓰기 규칙 `interact` (주인·참여자), 나머지는 `admin`.
- **고를 때 표를 다시 그리지 않는다** (초점·스크롤 유지). 저장소 소식이 오면 다시 그리되 고른 것은 Map 으로 남긴다.
- **분류·상태 거르기만 브라우저에 기억** (`localStorage`, 실패해도 그대로). 고른 것·의견은 기억하지 않는다.
- 링크 `#…` 은 편집기가 지금 읽는 방식 그대로: 캐릭터 `#<slug>`·`#<slug>.talk`, 배경 `#<slug>`·`#furn-<slug>`·`#item-<slug>`·`#wp-0N`·`#rm-0N`, 숫자 표 `#<표 id>`, 곡 편집기 `#songs|schedule|sfx|voices`. 테스트가 그 편집기 코드에 그 모양이 있는지 본다.
