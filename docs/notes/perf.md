## 정한 것

- **카메라**: 하늘 띠는 각도만 낮추면 나무가 더 가리고, 곡면만 세게 하면 땅이 너무 굽는다 → 둘을 같이 (22°·0.0064). 기본 확대(0.15)에서 광장 화면 위 5~8% 하늘, 선착장도 띠가 보인다. 멀리(줌 1)는 섬 내려다보기라 하늘이 거의 없다. 집 안은 W3 의 `CAMERA_BOX`(방이 다 보이는 범위)가 예전 각도 기준이라 예전 값 유지.
- **가림 투명 = 디더**: 반투명(블렌딩)은 InstancedMesh 정렬·외곽선 껍데기·W4 셰이더와 얽혀 깨지기 쉽다 → 버리기(discard)만 쓰는 디더. 4×4 바이어라 FXAA·틸트 흐림 뒤에는 옅은 유령처럼 보인다. 70% 만 지워 물체가 있다는 건 남긴다. 키 작은 것(꽃·바위·덤불·울타리·가로등)은 대상에서 뺐다.
- **대화 상대**: town 이 아직 `world.occlusion.watch` 를 안 쓰므로, `ctx.services.town.villagers[i].mode === 'talk'`·`keepers[i].mode === 'talk'|'talk-walk'` 인 주민의 `actor.position` 도 대상으로 본다 (town 의 개발용 서비스, 계약 밖 — 아래 제안).
- **해안선**: 모델(타일)은 안 건드리고 바다 칸에 모래 비탈을 깐다. 문턱 0.28(0.5 보다 바깥)로 등고선을 부풀려 튀어나온 칸 모서리까지 비탈 윗면(-0.008, 모래 타일 윗면 바로 아래)에 묻힌다 — node 로 확인: 땅 칸 모든 모서리가 거리 ≤ 0.08칸, 거기 비탈 높이 -0.015. 물가 선은 해안선에서 0.44칸 바깥. 강물은 땅이 아니라서 강어귀는 열린 채로 둥글게 감긴다.
- **그리기 호출 줄이기**: 이 GPU(인텔 내장 + D3D11 ANGLE)에서는 그리기 호출 하나가 약 40µs(다른 창과 GPU 를 나눌 때) — 호출 수가 크게 먹는다. 16×16 구역 묶음(섬 하나 180여 개)을 종류마다 하나(48개)로 합치고, 화면 밖 판정은 칸마다 CPU 에서 (곡면·그림자 카메라 반영). 같은 프레임을 판정 켜고/끄고 그려 비교: 5장면 중 4장면 화소 하나도 안 다름, 선착장 83화소(헤엄치는 물고기 그림자로 보임).
- **그리는 순서**: 땅 셰이더가 화면 대부분을 칠한다 → 땅을 물체 다음에(`renderOrder 1`), 바다를 맨 나중에(`2`). 나무·집에 가린 땅 조각은 깊이 시험에서 버려진다 (광장 처리량 16.96 → 14.21ms). 하늘 돔을 맨 뒤로 보내 보기도 했는데 나아지지 않아 sky 는 그대로 뒀다.
- **자동 품질**: GPU 타이머만 보면 안 된다 — 60fps 에 맞춰 쉬는 GPU 는 클럭을 내려 같은 일을 더 오래 한다(처리량 10.3ms 인 장면이 타이머로는 12.6ms). 그래서 **실제 프레임 간격(rAF) 가운데 값 > 22ms 이고 GPU 시간 > 10ms** 일 때만 low 로 (확장이 없으면 간격만). 시작 뒤 2.5초 건너뛰고 3초(표본 60개 이상) 잰다. 50ms 넘는 간격(숨겨진 창·멈춤)은 버린다 → 미리보기 창이 숨어 rAF 가 1초에 한 번일 때도 잘못 낮추지 않는다. 주소에 `?quality=` 가 있거나 이미 low(터치 기기)면 재지 않는다. 낮추기만 하고 올리지는 않는다.
- 런타임에 그림자 종류(PCF ↔ PCFSoft)는 바꾸지 않는다 — 모든 셰이더를 다시 만들어 1~3초 멈춘다. 재 보니 둘의 GPU 차이도 거의 없었다.

### 재는 법 (다음 사람을 위해)
- 미리보기 창이 숨겨지면 rAF 가 멈춘다 → `renderer.setAnimationLoop(null)` 후 `ctx.step(dt)` 로 돌린다.
- `gl.finish()` 는 Chrome 에서 기다리지 않는다. `readPixels` 1화소로 기다리면 그 자체가 6~7ms 든다. GPU 타이머 쿼리는 프레임마다 기다리면 GPU 가 클럭을 내려 값이 뒤섞인다 → **여러 프레임을 연달아 그리고 한 번 기다리는 처리량**으로, 두 설정을 번갈아 여러 번 잰다.
- 다른 세션(미리보기 창)이 같은 GPU 를 쓰면 값이 1.5~2배로 튄다. 절대값보다 같은 때 번갈아 잰 차이를 본다.

## 계약 제안 (합칠 때 `docs/CONTRACTS.md` 에 반영 부탁)

**world**
1. `world.occlusion = { watch(getPoint) → 해제 함수, enabled, list() }` — `getPoint()` 가 `{x, y(발 높이), z}` 를 돌려주는 동안 카메라와 그 점 사이 나무·건물이 비친다. 플레이어는 늘 들어 있다.
2. `world.prepareFrame()` — 그리기 직전에 render 가 부른다 (배경 묶음의 칸마다 화면 밖 판정). 다른 그리기 길에서는 world.update 가 한 프레임 늦게 대신 한다.
3. `world.coastDistance(x, z)` → 부드러운 해안선에서 바다 쪽 거리(칸, 땅 안 ≤ 0), `world.coastWaterline` (≈ 0.44). 거리 < 물가 선이면 그 바다 칸 자리는 모래 비탈 위라 물이 안 보인다.
4. kit 묶음 안쪽(`Batch.flush` 없어짐, 칸 순서 = 가까운 순)은 world 안에서만 쓴다. 바깥 모듈은 지금처럼 `objects.*` 만.

**render (style)**
5. `style.setQuality('high' | 'low', { auto })`, `style.quality`, `style.autoQuality`(판단 결과), 이벤트 **`quality:changed {quality, auto}`**. `ctx.quality` 는 **도중에 high → low 로 바뀔 수 있다** — init 때 한 번 읽어 두는 모듈은 이 이벤트를 들을 것 (gather 의 곤충·물고기 수는 매번 읽어서 괜찮다).
6. render 가 프레임마다 `renderer.info.reset()` (autoReset 끔) → `renderer.info.render.calls/triangles` 가 화면 효과 패스까지 합친 한 프레임 값이다 (`?debug` 왼쪽 아래 표시도 이제 맞다).
7. 뼈대 메시(캐릭터)는 render 가 `frustumCulled = true` 로 바꾸고 `boundingSphere` 를 매 프레임 넣는다. **늘 그려야 하는 뼈대 메시가 있으면 그 뒤에 `frustumCulled = false`** 로 두면 render 가 건드리지 않는다. 뼈대(`Skeleton`)마다 `update` 를 감싸 안 보일 때 건너뛴다.

## 다른 트랙에 부탁

- **W2/town** (주민): 대화 상대가 나무 뒤에 있어도 보이게 지금은 world 가 `town.villagers[].mode` 를 들여다본다. `beginTalk` 에서 `const off = world.occlusion?.watch(() => actor.position)`, `endTalk` 에서 `off()` 로 바꿔 주면 계약 밖 의존이 사라진다.
- **W1/gather** (낚시): 바다 칸 147개(1623개 중)는 가운데가 이제 모래 비탈 밑이다 (해안 오목한 곳). 물고기 그림자가 거기 생기면 모래에 묻혀 안 보인다 → `habitatAt` 의 바다 판정에 `world.coastDistance?.(x, z) > world.coastWaterline + 0.3` 을 더해 주세요 (헤엄칠 목표 자리도 같게).
- **X1/휴대폰**: 카메라 세로 시야는 32° 고정이라 세로 화면에서는 좌우가 좁다. 세로 화면용 각도·거리가 필요하면 `camera.js` 의 `PRESETS` 를 같이 정하자 (콘솔에서 `(await import('/src/player/camera.js')).PRESETS.near.pitch = …` 로 바로 바꿔 볼 수 있다). 터치 기기는 처음부터 low 라 자동 판단은 안 돈다.
- **X4/배포**: 새 파일 `src/world/{occlusion,coast,coastfield}.js`, `src/render/{cull,quality}.js` 를 묶음에 넣어 주세요 (외부 파일·텍스처 없음, 해안 텍스처는 실행 중 만든다).
- **W4/셰이더(materials.js)** 제안: ① 디더 가림을 `materials` 공용(`look`/재질 uniform)으로 옮기면 캐릭터·가구도 같은 방식으로 비칠 수 있다. ② 캐릭터 한 명이 메시 7~12개 × (몸·외곽선·그림자)라 화면 안 주민이 많으면 호출이 크다(선착장 장면 ~190번) — kit 처럼 캐릭터 툰 부품을 꼭짓점 색으로 합치면 1/3 로 준다 (player·town·materials 같이 해야 함). ③ 고해상도(화소 배율 2) high 에서 FXAA 가 비싸다(1280×800 에서도 1.3ms) — 배율 ≥ 2 면 끄는 것도 생각해 볼 만하다.
