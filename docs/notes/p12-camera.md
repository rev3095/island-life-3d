# P12 시점 조작 — 하늘 올려다보기 (`p12-camera`)

사용자 요청: "마우스로 하늘 위로 올려다보려고 할 때 대응해서 시점을 하늘 올려다볼 수 있게 시점 조작 controlling 기능 추가".
지금 카메라는 남쪽 위에서 비스듬히 내려다보는 고정 각도라 하늘이 화면 위 5~8% 만 보였다 (v16 하늘 셰이더의 구름·빛살·은하수가 거의 안 보임).
이 트랙은 카메라를 잠깐 낮추고 위를 보게 하는 조작을 더한다. 기본 시점·걷기·장면 카메라는 그대로.

## 조작 방법

| 입력 | 하는 일 |
|---|---|
| 마우스 **오른쪽 버튼 끌기** (또는 가운데 버튼) | 위로 끌면 올려다보기, 아래로 끌면 내려다보기, 좌우로 끌면 둘레 돌기 (오른쪽으로 끌면 오른쪽을 본다) |
| **R** / PageUp (누르는 동안) | 올려다보기 |
| **V** / PageDown (누르는 동안) | 내려다보기 |
| Home | 바로 원래 시점 (돌아오기를 'stay' 로 둘 때 쓰는 키) |
| 휴대폰 **두 손가락 함께 끌기** | 위로 = 올려다보기, 좌우 = 둘레 돌기 |
| 휴대폰 두 손가락 벌리기·모으기 | 가까이·멀리 (예전 그대로) |
| 놓기·키 떼기 | 부드럽게 원래 시점으로 (약 1초, `LOOK.back`·`backSpeed`) |

- 화면 아래 키 안내(`ui/hud.js` `HINT_KEYS`)에 `우클릭 끌기 · R/V — 올려다보기` 한 줄.
- 둘레를 돌면 키보드·패드 방향도 같이 돈다 (화면 위쪽 = 카메라가 보는 쪽, `input.viewYaw` → `viewMove`). 마우스로 걷기는 땅 위 점이라 그대로.

### 겹침 정리
- **왼쪽 버튼 = 걷기** (`mouse.js` 는 `e.button !== 0` 이면 안 받는다 — 고치지 않음), **오른쪽·가운데 = 시점** (`camera.js`).
  같은 마우스의 두 번째 버튼은 브라우저가 `pointerdown` 을 보내지 않으므로, 끄는 중에 다른 버튼을 눌러도 서로 시작되지 않는다 (점검에서 확인).
- 오른쪽 메뉴(`contextmenu`)는 **캔버스에서만** 막는다 (창·글 칸에서는 그대로). 가운데 버튼 자동 스크롤도 캔버스에서만 막는다.
- 터치: 한 손가락은 예전처럼 아무것도 안 한다 (패드·A·B 가 따로). 두 손가락은 처음 움직임으로 하나를 고른다 — 손가락 사이가 28px 넘게 변하면 가까이/멀리, 가운데 점이 22px 넘게 움직이면 시점. 고른 순간을 기준으로 다시 잡아 튀지 않는다.
- 키: R·V·PageUp·PageDown·Home 은 `input.js` 의 `KEYS`·`MOVE`·확대(−/=)·H 와 겹치지 않는다 (`tests/camera.test.mjs` 가 검사). F 는 줍기라 쓰지 않았다.

## 모양 (값은 `src/player/camera.js` 의 `LOOK`)

`tilt` −1(끝까지 내려다보기) ~ 0(원래) ~ 1(끝까지 올려다보기), `yaw` = 둘레 돌기. 계산은 순수 함수 `lookView(base, tilt, yaw)`.

| 값 | 지금 | 뜻 |
|---|---|---|
| `upElev` | 4° | 끝까지 올려다볼 때 카메라 높이각 (초점에서 본). 원래 22°(가까이)~40°(멀리) |
| `upAim` | 12° | 그때 지평선 위로 보는 각 |
| `upFov` | +16° | 시야각을 넓힌다 (32 → 48, 세로 화면 46 → 62). 흔들림 줄이기면 `calmFov` 0 |
| `upDist` | 9칸 | 그때 거리 (확대와 상관없이 같은 모습) |
| `upCurve` | 0.0030 | 그때 곡면 세기 (기본 가까이 0.0064 — 낮게 보면 땅이 너무 빨리 넘어간다) |
| `downElev` · `downDist` | 62° · ×1.08 | 끝까지 내려다볼 때 |
| `yawMax` · `sideCurve` | ±60° · 0.25 | 둘레 돌기 한계, 옆으로 90° 돌았을 때 곡면 배율 (아래 「둘레 돌기와 곡면」) |
| `dragY` · `dragX` | 0.0055 · 0.0050 | 끌기 감도 (화소당). 위로 180px 끌면 끝까지 |
| `touchY` · `touchX` | 0.0075 · 0.0060 | 두 손가락 감도 |
| `keyRate` | 1.6/초 | R·V 누르는 동안 |
| `back` | `'release'` | 돌아오기: `'release'` 놓으면 · `'walk'` 걸으면 · `'stay'` 그대로 (Home) |
| `backSpeed` · `calmBack` | 3 · 1.6 (1/초) | 돌아오는 빠르기 (3 ≈ 1초면 거의 다, 흔들림 줄이기는 더 천천히) |
| `follow` · `calmFollow` | 14 · 7 | 끌기를 따라가는 부드러움 |
| `clear` | 0.35칸 | 카메라와 땅 사이 여유 |

끝까지 올려다보면 (1280×800): 지평선이 화면 아래 1/4~1/3, **하늘이 화면 70% 남짓**, 플레이어는 화면 아래쪽 (머리가 하늘 앞에). 세로 휴대폰은 하늘 60% 남짓.
`tests/camera.test.mjs` 가 가로·정사각·세로 화면 × 가까이·기본·멀리에서 "곡면 지평선 위 하늘 > 60%, 플레이어 몸·발 화면 안" 을 계산으로 확인한다.

## 올려다볼 때 어색한 것 처리

- **곡면 월드**: 카메라가 낮으면 곡면(가까이 0.0064)이 땅을 15칸 앞에서 넘겨 버려 작은 행성처럼 보인다 → 올려다볼수록 `upCurve` 0.0030 쪽으로 (지평선 ≈ 22칸 앞).
- **땅 속 안 들어가기**: `clearY` — 초점에서 카메라까지 6점을 보고 보이는 땅(땅 높이 − 곡면으로 내려간 만큼) + 여유 위로 선이 지나게 카메라를 올린다. 올릴 땐 바로, 내릴 땐 천천히. 올린 만큼 같이 내려다봐서 플레이어가 화면 같은 자리에 남는다. 여유는 올려다볼수록 0 → 0.35 (원래 시점은 여유 0 이라 예전과 같다).
- **건물·나무**: 카메라가 낮으면 카메라 바로 앞 나무·집이 플레이어를 가린다 → 가림 투명(`world/occlusion.js`)이 디더로 비치게 한다. 찾는 범위가 "대상에서 남쪽으로 3.2칸 둘레 4.6칸" 이라 낮은 카메라 가까이 물체를 못 찾았다 → **카메라 쪽 방향**(둘레를 돌아도)으로, 카메라가 낮으면(높이각 17° 아래) 카메라까지 덮게 넓혔다. 원래 시점은 범위가 그대로. 광장 나무 아래·집 북쪽에서 올려다본 스크린샷에서 확인.
- **그림자 범위**(`render/cull.js` `fitRect`): 보이는 땅을 "북쪽으로 21칸까지" 잘랐다 → "카메라가 보는 수평 방향으로 21칸" (원래 시점은 같은 식). 올려다보면 위 모서리 광선이 땅을 안 만나 이 자르기로 끝난다.
- **화면 밖 빼기**(`world/kit.js` 칸 판정, `render/cull.js` 캐릭터): 카메라 절두체 + 곡면 보정이라 새 각도에서도 맞다 (고치지 않음). 다만 낮은 사양의 그리는 거리(`DRAW_FAR` 낮음 28 · 매우 낮음 22칸)는 올려다보면 지평선 근처 먼 물체가 빠진 것이 보일 수 있다 — 곡면 0.0030 의 지평선이 22칸 안팎이라 거의 안 보였다.
- **막힘**: 집 안(`setBounds`)·장면(`story.playing`, 시작하면 `story:start` 로 바로 원래)·창이 열린 동안(`ui.isBlocking`·`input.enabled`)은 조작을 받지 않고 원래 시점으로 돌아간다. 순간이동(`snap` — 집 드나들기·장면 끝)도 원래대로.
- **흔들림 줄이기**(`ui.access.calm`): 시야각을 넓히지 않고(`calmFov` 0), 돌아오기·따라가기를 더 천천히.

### 둘레 돌기와 곡면
곡면 월드 셰이더(`core/materials.js`)는 **z(남북)로만** 휜다 (`y -= (z − 초점 z)² · uCurve`). 그래서 옆으로 돌면 땅이 좌우로 넘어가 보인다 → 둘레 돌기는 ±60° 까지, 옆으로 돌수록 곡면을 `sin²` 로 줄인다 (60° 에서 곡면 ×0.44). 동쪽을 보면 바다 지평선이 평평하게 보인다.
360° 돌기를 하려면 곡면을 "보는 방향 기준"으로 바꿔야 한다 (아래 제안).

## 사용자에게 물을 선택지 (보드에 올릴 거리)

1. **놓으면 돌아오기** — A 놓으면 돌아오기 (지금, 동물의 숲처럼 잠깐 보기) · B 놓아도 그대로, 걸으면 돌아오기 · C 그대로 두고 Home 으로 되돌리기. (`LOOK.back`)
2. **돌아오는 빠르기** — A 약 1초 (지금, `backSpeed` 3) · B 약 2초 (1.5) · C 약 0.5초 (6).
3. **얼마나 올려다볼까** — A 지평선 위 12° + 시야 +16° (지금, 하늘 70% · 플레이어 화면 아래) · B 20° (하늘 85%, 플레이어는 화면 밖) · C 8° (하늘 60%, 플레이어가 더 잘 보임).
4. **좌우 둘레 돌기** — A ±60° (지금) · B 없음 (위아래만, 동물의 숲 식) · C 한 바퀴 (곡면 셰이더를 보는 방향 기준으로 바꾸는 제안이 먼저).
5. **끌기 방향** — A 위로 끌면 올려다보기 (지금, 1인칭 게임 식) · B 뒤집기 (위로 끌면 내려다보기, 땅을 잡아 끄는 느낌).
6. **섬폰 설정에 넣을지** — 돌아오기 방식·끌기 뒤집기·감도를 섬폰 설정 칸으로 (ui 트랙, `state.settings`).
7. **높음 사양의 틸트 흐림** — A 올려다볼수록 흐림을 줄인다 (제안, render 트랙) · B 그대로 (올려다보면 마을이 뿌옇게).

## 다른 트랙에 제안 (이 브랜치에서는 고치지 않음)

- **하늘(`src/sky/`, 하늘 검수 보드)**: `SKY_FX` 의 구름 높이·크기·흐름은 "화면 위 1/5 하늘 띠" 에 맞춘 값이다. 올려다보면 하늘의 50~70° 위까지 보이므로 구름층(`cloudScale`·`cloudClear`)과 천정 쪽 그라데이션(`smoothstep(0.18, 0.8, e)`)을 올려다본 화면으로도 고르면 좋다 — 보드에 "올려다보기" 장면 칸을 더하자. 3D 솜구름(`clouds.js`, 북쪽 먼 하늘)은 올려다보면 지평선 바로 위 큰 덩어리로 보인다 (스크린샷 `02-up-day`).
- **화면 효과(`render/post.js`, 높음만) — 먼저 고칠 것**: 틸트 흐림(cozy 위 1.2 · 아래 0.45 · 또렷한 줄 0.5 · 폭 0.4)은 "화면 위 = 먼 곳" 이라 올려다보면 맞지 않는다 — 하늘(위)이 흐려지고, 화면 아래쪽에 내려온 마을·플레이어가 아래 흐림에 들어가 뿌옇다 (`p12-camera-shots/12-up-day-high-tilt.png`, 적정 이하는 화면 효과가 없어 괜찮다). `player.camera.look.tilt` 를 읽어 올려다볼수록 `tiltTop`·`tiltBottom` 을 0 쪽으로 줄이는 것을 제안 (render 의 `apply` 에 곱 하나).
- **곡면 셰이더(`core/materials.js`)**: 곡면 중심 축을 `uCurveDir`(카메라가 보는 수평 방향)로 두면 둘레 돌기를 한 바퀴까지 열 수 있다. 같이 고칠 곳: `mouse.js` `groundPick`, `world/kit.js` 칸 판정, `world/occlusion.js`, `render/cull.js` 의 `dz²`.
- **계약**: `ctx.input.look` (`{ y }` 시점 키) · `ctx.input.viewYaw` (카메라가 넣음) · `player.camera.look` (확인용 `{ tilt, yaw, tiltGoal, yawGoal, dragging }`) · `player.camera.setLook(tilt, yaw)` 를 더했다. 장면·집 쪽은 바꿀 것 없음 (`snap`·`setBounds` 가 시점 조작도 원래대로 돌린다).
